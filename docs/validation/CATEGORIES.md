# Validation categories

| ID | Category | Asks |
|----|----------|------|
| V-ARCH | Architecture | Engines modular? Domain/campaign/claims separated from code? |
| V-SCI | Scientific validity | Contracts, pillars independent, failure modes mapped? |
| V-SOFT | Software quality | Typed configs, no silent except, import graph healthy? |
| V-REPRO | Reproducibility | Seeds, manifests, environment pins, twin-run diff? |
| V-ROB | Robustness | Stage 14 battery + failure detectors fire under stress fixtures? |
| V-EXT | Extensibility | Domain profile swap; claim pack add; QA check register? |
| V-TRANS | Transparency | Docs without case conclusions; messages; dossiers? |
| V-TRACE | Traceability | EvidenceItem.source → file; claim pack id on register; ledger links? |

Each suite test declares one primary category (and optional secondary).
